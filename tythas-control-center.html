A multi-tenant website management platform that replaces fragmented client logins with one central dashboard for CMS, SEO, leads, and uptime.

The problem

Tythas is the digital agency I run. The moment a client site shipped, it became its own disconnected island — a separate WordPress admin, a different hosting cPanel, sometimes an ad-hoc script I'd written once and never documented.

There was no single place to see which sites needed attention, no consistent way to publish a page across different tech stacks, and nothing watching for SEO gaps, lead capture failures, or server uptime.

A five-minute copy change became an urgent developer ticket for me personally, and more than once I learned about a broken form or expired SSL certificate directly from the client — not from an automated system.

Key decisions

Four pivotal product decisions shaping ergonomics, safety, and operations.

Decision 01

Universal Connector Bridge vs. Bespoke Client Plugins

Options considered

Considered writing bespoke WordPress plugins per client repo, or forcing all clients into a rigid headless CMS migration with high maintenance overhead.

What I chose and why

Engineered a universal decoupled connector bridge. Abstracted WordPress REST APIs and Next.js server webhooks behind a single capability layer so operators never need to know the underlying stack.

1

Unified Dashboard Surface

One consistent authoring UI regardless of target CMS or custom framework.

2

Decoupled Capability Handshake

Verifies read/write permissions before unlocking any publishing controls.

3

Multi-Stack Client Targets

Directly bridges to WordPress, Next.js, and static webhooks without client plugins.

Decision 02

Continuous WYSIWYG Ergonomics vs. Block-Picker Friction

Options considered

Built an experimental Notion-style block editor with nested slash commands and floating inspector panels.

What I chose and why

Client testing revealed immediate friction ('We just need a writing box like classic WordPress'). Grounded in Jakob's Law, I pivoted to a continuous writing canvas with 10 persistent top-level tools and instant mobile viewport emulation.

1

10-Icon Persistent Toolbar

Essential formatting visible without digging through nested block menus (Hick's Law).

2

Inline Structured FAQ Accordion

Writing copy automatically outputs valid Schema.org JSON-LD structured data.

3

Instant Mobile Viewport Emulation

390x844 responsive preview updates in real-time as content is drafted.

Decision 03

Connection-State Gating for Defensive Operations

Options considered

Considered optimistic UI where publish buttons are always active, displaying error toasts only after network failure.

What I chose and why

Adopted strict 4-state connection gating (Disconnected → Audit Only → Analyzing → Connected). Grounded in Postel's Law and Error Prevention: write actions are physically disabled until the bridge verifies live API authenticity.

1

4-Phase Verification Machine

Sites progress systematically through verified capability states before write access.

2

Gated Write Interception

Locked state disables destructive buttons with clear guidance preventing ghost clicks.

3

Verified Edge Execution

Live buttons unlock only when cryptographically signed webhooks are confirmed.

Decision 04

Single Attention Queue vs. Distributed Notification Feeds

Options considered

Considered keeping notifications isolated within their respective tabs (CMS tab, SEO tab, Uptime tab) or relying on email alerts.

What I chose and why

Aggregated all high-priority operational signals across every client domain into one centralized Priority Attention Queue, sorted by severity (Critical, Warning, Leads).

1

Severity-Based Filtering

Immediate triage tabs for Critical outages, Warnings, and Inbound Leads.

2

Cross-Tenant Domain Attribution

Clear badges designate which client property requires operational intervention.

3

One-Click Direct Action

Direct deep-links allow immediate renewal or response without switching contexts.

Eisenhower Prioritisation Matrix & 5-Whys Root Cause Analysis ▾

Eisenhower Matrix

Do First (Urgent/Important): Fix missing CSS custom token in globals.css causing invisible input text across 7 modal files.

Schedule (Important/Not Urgent): Build Test/Demo Mode for live prospective client presentations.

Delegate/Hotfix: Feature-flag unverified buttons during live stakeholder calls.

5-Whys: The Invisible Text Defect

Input text was white on white → Used custom utility `bg-surface-hover` → Referenced `--color-surface-hover` → Property was undefined in globals.css → Tailwind silently dropped undefined classes. Declaring the token at root instantly fixed all 99 instances.
