01

Problem Statement: Every Client Site Was Its Own Island

Tythas is the digital agency I run. The moment a client site shipped, it became its own disconnected island — a different WordPress admin, a separate hosting cPanel, sometimes just an ad-hoc script I'd written once and never documented anywhere.

There was no single place to see which sites needed attention, no consistent way to publish a page or a post across different tech stacks, and nothing watching for SEO gaps, lead capture failure, or server uptime. A five-minute content change often became an urgent ticket for me personally, and more than once I heard about a broken form or an expired SSL certificate directly from the client — not from an automated system.

Objectives & Goals: No Broken Promises

Four ironclad guarantees the platform had to deliver for agency operations

CONSOLIDATE

Replace N Logins With One

Every client site — whether running standard WordPress or a custom Next.js/Node stack — must be editable from the same administrative console, under unified roles and role-based access control (RBAC).

NEVER LIE

No Control That Silently Fails

A write action only ever renders active once the platform has verified live API capability. Never present a save button that looks functional but isn't wired to live infrastructure.

REDUCE

Content Work I Don't Have to Do Myself

Publishing a page, authoring a blog post, setting up a 301 redirect, or embedding a lead capture form should never require opening VS Code or deploying code manually.

SURFACE

Problems Before the Client Finds Them

Uptime outages, missing canonical tags, structured data gaps, and inbound leads land in one central attention list rather than staying invisible until something breaks.

Research & Observations: Built by Its Own Primary User

Self-ethnography and empirical observation of recurring agency bottlenecks

01 · Data Model Bottleneck

Every new client project meant re-deciding where SEO fields, redirects, and schema would live — demonstrating that the underlying data schema, rather than the content itself, was the true recurring barrier.

02 · Sales Demo Friction

The Custom connector's "publish live" promise had no way to be demonstrated to a prospective client without a live backend already in place — a major sales blocker only discovered during real client pitching.

03 · Editor Complexity Rejection

An early screenshot of my custom block-based editor received immediate feedback: "Very complex — we just need a simple writing box like classic WordPress." This sparked a total UX pivot toward familiar WYSIWYG patterns.

04 · Silent Token Defect

One undefined CSS variable surfaced as invisible white-on-white input text in a single modal — proving the Tailwind token system itself required a systemwide audit across all 99 usage points.

Unique Features: The Architectural Moat

Key design decisions separating Tythas Control Center from conventional tooling

INNOVATION 01

Connector Abstraction

Custom-built Next.js and static web apps are first-class citizens alongside WordPress instances, writing through a standardized platform API bridge rather than requiring bespoke client plugins.

INNOVATION 02

Connection-State Gating

A site progresses through 4 explicit states: Disconnected → Audit Only → Analyzing → Connected. No write action ever renders unless the system verifies end-to-end write capabilities.

INNOVATION 03

One Attention List

Instead of dispersing warnings across separate inboxes, technical SEO flaws, critical uptime drops, and incoming lead opportunities converge into a single prioritized operational triage queue.

5 Whys & Root Cause Analysis: The Invisible-Text Defect

Investigating how a silent design token failure escaped into production

Problem: Why was modal form input text invisible to users?

1 Why? The input element's background color and text font color were completely identical.
2 Why? The component was using a bg-surface-hover custom Tailwind utility class.
3 Why? That utility referenced a CSS custom variable, --color-surface-hover.
4 Why? That custom property was never defined in any of the four theme blocks inside globals.css.
5 Root Cause: Tailwind CSS silently drops unrecognized utility classes with zero build-time warnings — allowing a missing token to persist unnoticed across 7 files and 99 usages until visually caught.
Fix Applied: Declared the CSS custom token once at its single source of truth in globals.css, instantly remediating all 99 defective UI instances in a single two-line commit.

UI/UX Laws Applied: Cognitive Principles in Action

Grounding interface decisions in established behavioral psychology

JAKOB'S LAW

Familiar Mental Models

The blog editor was pivoted from an experimental multi-block picker back into a continuous writing canvas with a top formatting bar — the exact interaction model familiar to millions of WordPress users.

HICK'S LAW

Minimising Decision Time

Formatting options are consolidated into 10 persistent toolbar icons rather than deep nested menus, ensuring writing never requires pausing to configure block formats.

MILLER'S LAW

Information Chunking

The complex Site Health dashboard groups dozens of telemetry signals into 6 logical category tiles instead of presenting an intimidating, unmanageable wall of raw metrics.

POSTEL'S LAW & ERROR PREVENTION

Defensive State Gating

Connection-state gating prevents user error by never exposing write actions unless the domain's webhook authenticity and server readiness are cryptographically verified.

DOHERTY THRESHOLD

Sub-400ms Feedback

The rich-text editor autosaves inline in the background without modal loaders or UI freezing, maintaining immediate perceived responsiveness that protects writer flow state.

VON RESTORFF EFFECT

Visual Isolation of Primary Actions

Irreversible actions like "Publish Live" use the solitary vibrant indigo-to-purple gradient in an otherwise neutral dark UI, ensuring the critical write trigger is visually unmistakable.

Design & Technical Challenges: Three Bugs, Three Lessons

Reflections from full-stack implementation and design system audits

CHALLENGE 01

Invisible Text Across 99 Places

Cause: Missing CSS custom token --color-surface-hover silently dropped by Tailwind.
Lesson: Design tokens must be audited with automated linting rules rather than assumed valid.

CHALLENGE 02

Modal Trapped Under Ancestor Blur

Cause: A backdrop-filter CSS property created a new stacking context, clipping a position: fixed modal.
Lesson: Render all overlay modals using React Portal pinned directly to document.body.

CHALLENGE 03

Overcomplicated Block Editor

Cause: The initial editor closely matched the CMS database schema at the expense of writing ergonomics.
Lesson: UX simplicity must be designed as an intentional abstraction layer over complex data schemas.
